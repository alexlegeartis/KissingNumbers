# Larger-compute search in dimensions 17 and 20, 4 November 2026

This campaign has not produced an improved kissing configuration. Its verified
starting values are **5730 in dimension 17** and **19448 in dimension 20**.
The principal new negative result is an exact ceiling for a finite family of
nonuniform 20D vectors. All scope restrictions below matter.

The comparison is Cohn–Li, *Improved kissing numbers in seventeen through
twenty-one dimensions*, [arXiv:2411.04916v3](https://arxiv.org/html/2411.04916v3),
and [Cohn's table](https://cohn.mit.edu/kissing-numbers/). The current paper's
table states 5730 and 19448. A direct request for the table returned HTTP 502;
the search index also returned those values. This is a dated source check,
not a guarantee that no unpublished construction exists.

## Exact certificate for the nonuniform 20D family

For a nonnegative integer profile `p`, let `Q = sum p_i^2`. Its vectors are
`sqrt(8/Q) * p_i * (-1)^c_i`, where `c` is a 4-punctured Golay word. Compatibility
with every fixed root and odd signed octad reduces to integer inequalities:

```
2 (p_i + p_j)^2 <= Q
(sum_{i in O} p_i - 2 min_{i in O} p_i)^2 <= 2 Q
```

All 267 profiles pass these checks. For two profiles and a sign difference,
write `D = sum p_i q_i (-1)^c_i`. Compatibility is exactly
`D <= 0 or 4 D^2 <= Q_p Q_q`. Every decision in the certificate uses Python
integers; no floating point or optimization solver enters the proof.

The punctured Golay code has five weight-four words, supported on five
disjoint tetrads. At most one profile can be used on any one sign word.
For each profile, the certificate checks all 267 possible partner profiles
and finds that compatible neighbors can occur along **at most one** of these
five tetrad directions. Of the 267 profiles, 261 allow none and six allow one.

Partition the 4096 sign words into the 1024 squares generated by two tetrad
directions. Three selected words in any square would give its middle word two
selected tetrad neighbors, which the preceding integer comparisons forbid.
Thus at most two words can be selected per square, for an added layer of at
most 2048 points. The uniform profile and the original 2048-word distance-five
subcode attain the bound. Consequently this **specific 1093632-candidate
dense family over the fixed base** has exact ceiling `17400 + 2048 = 19448`.

This does not bound arbitrary magnitude profiles, sign words outside the
punctured Golay code, changes to the fixed base, or the unrestricted kissing
number. The replay is:

```sh
OPENBLAS_NUM_THREADS=1 taskset -c 0-126 python certify_profiles20.py
```

See `data/profile_ceiling_certificate.json`, which includes the input SHA-256.

## Verification and reproducibility

The machine exposes 128 logical EPYC CPU threads and about 472 GiB RAM. A
repository instruction added during the campaign reserves logical CPU 127;
subsequent commands use `taskset -c 0-126`. The RTX A4000, 16 GiB, is visible
outside the execution sandbox; GPU jobs require the executor's supported
escalated mode. Device 0 was rechecked before using it. The GT 1030 is unused.

`data/independent_verification.json` records a separate exhaustive check of all
pairs in the 5730- and 19448-point baselines, 20000 scalar/graph cross-checks
of the enlarged 17D graph, 2000 independently expanded orbit-pair checks per
20D model, and checks of all saved discrete solver incumbents. A duplicate-point
corruption control is rejected. CPU/GPU numerical deformations have separate
reports, explicitly marked uncertified. The GPU gradient is checked against
independent finite differences before each run.

Use the working directory containing this README. Dependencies are NumPy,
SciPy, OR-Tools 9.15, and PyTorch 2.6 for GPU runs. Install these in the Python
environment used for the commands below. The original campaign used a local
OR-Tools installation in the surrounding workspace's `.compute-deps`.

```sh
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
taskset -c 0-126 python prepare17.py
g++ -O3 -mavx2 -fopenmp -std=c++17 build_graph.cpp -o build_graph
taskset -c 0-126 ./build_graph data/vertices17.bin data/graph17.bin 64
taskset -c 0-126 python orbits17.py --rank 4 --constant 0
taskset -c 0-126 python prepare20.py --rank 8 --seed 1
taskset -c 0-126 python prepare20.py --rank 7 --seed 1
taskset -c 0-126 python prepare20.py --rank 6 --seed 2
taskset -c 0-126 python verify.py
taskset -c 0-126 python certify_profiles20.py
```

`solve_quotient.py` builds bounded exact CP-SAT models. Its 20D uniform-sign
models use Hamming balls of radius two as clique constraints, and conditional
constraints for octad conflicts. `clique_cover.cpp` compresses a saved graph
into equivalent at-most-one constraints, verifies every clique and that every
edge was covered, and publishes the completed cover with an atomic rename.
The 17D symmetry branch fixes one selected positive flat; bounds from that
branch say nothing about a hypothetical configuration without any flats.

The completed rank-eight 20D solve can be repeated with:

```sh
taskset -c 0-126 python solve_quotient.py q20_r8_s1 --seconds 300 --workers 8 --seed 99
```

`search.cpp` shares a read-only graph across workers and saves any improvement.
`export_search.py` writes its metadata input. Example:

```sh
g++ -O3 -march=native -fopenmp -std=c++17 search.cpp -o search
taskset -c 0-126 python export_search.py full17
taskset -c 0-126 ./search data/graph17.bin data/full17.search data/full17_rerun 600 24 17001 5731
```

`profiles20.py` samples vertices and rational points on segments of the
admissible magnitude polytope. The certified input is the saved JSON;
rerunning randomized or numerical sampling is not required for proof replay.
`holes.py` supplies LP-ascent insertion directions. `gpu_deform.py` performs
memory-bounded float64 collective deformation on the A4000.

Large regenerable graphs and executables are ignored by this directory's
`.gitignore`. No main README, claimed result, or published-bound registry was
changed. Unrelated work elsewhere in `research/` was left intact.
