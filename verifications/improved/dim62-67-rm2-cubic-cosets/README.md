# Eighty cubic cosets of RM(2,6)

The 80 integers in `witness.txt` specify homogeneous cubics in six binary variables. Coordinates are the integers 0 through 63 in binary. The degree-three monomial masks are the 20 integers of weight three in increasing order; the corresponding bit of each witness integer is the monomial coefficient. For each cubic take its truth table plus every polynomial of degree at most two. The latter evaluation code has 22 independent generators (1 constant, 6 linear, 15 quadratic), reconstructed directly. This gives 80 disjoint cosets, each of size 2^22. Map binary values to signs (+1 for zero, −1 for one). Norm squared is 64 and binary distance at least 16 implies product at most 32.

The compact rule is ten translates of an eight-element subgroup in
the space of cubic coefficients. The second and third lines of
`cubic80.wins` give the ten offsets and the subgroup, respectively.
Coefficient addition is bitwise XOR; every resulting label is then
lifted by every quadratic Boolean polynomial. The replay checks this
factorization against the literal witness.

## Exact verification

```sh
g++ -std=c++17 -O3 verify80.cpp -o /tmp/verify_rm2_cubic80
/tmp/verify_rm2_cubic80 witness.txt
```

The replay checks the unique 176 pair-difference types (including same-coset differences) by direct scalar popcount against all 4,194,304 quadratic words, generated by Gray recurrence. All minima are exactly 16. It does not use the optimizer, GL(6,2) orbit classification, an inferred minimum, or precomputed distances. The resulting layer contains **335,544,320** points.

## Constructions with inherited sparse layers

Any norm-64 sparse point with body L1 norm at most 32 automatically coexists with every dense point. In particular amplitude-2 weight-16 points, amplitude-4 weight-4 points, and amplitude-8 poles have L1 norms 32, 16, and 8. Thus the proven sparse families in `dim61-67-compatible-sign-families` can be retained when the old dense code is replaced here.

* 64D: 335,544,320 + 32,768×2,048 + 10,416×16 + 128 = **402,819,968**.
* 65D: the 64D construction at zero last coordinate plus its two axial poles gives **402,819,970**, without requiring compatibility with old dense-owner lifts.
* 66D: 335,544,320 + (34,028+1,938)×2,048 + 11,088×16 + 132 = **409,380,228**.
* 67D: predecessor 355,095,446 minus its 268,435,456 dense points plus 335,544,320 = **422,204,310**, retaining the full proven weight-16 signed pools, small affine sign subcodes, four-supports and poles.

The predecessor 62D hexagon construction uses the same length-64 minimum distance of 16, fixing one bit and projecting three other marked bits to six heads. Each of the 80 cosets projects onto all four bits with rank four: on any four distinct binary points a relation annihilating affine functions would have to be the full four-point parallelogram, and a product of two independent appropriate linear functions separates one corner in that case. Each occupied head therefore has 80×2^18 words. The body unit amplitudes are unchanged, so the proven tail-zero sparse and four-support families remain; the head norms remain two, so poles remain. The inherited pair test uses only the full length-64 binary distance and Hamming distance between labels. Thus **147,704,844** points result: 6×80×2^18 + 10,610×2,048 + 9,145×16 + 124.

The 64D construction is not claimed to be optimal. The 63D transfer below uses a different and stronger section than the inherited balanced-octad section.

The checked 62D flag order is `(24,42,53,55)` (last flag zero); its heads correspond to labels `(0,1,3,7,6,4)`, in the original bit convention. `python transfer.py <path-to-dim61-67-compatible-sign-families>` checks the parent verification-source pin and five-dimension population manifest, rank four by literal quadratic evaluation, all 36 head-pair distance bounds, each dense/four-support type including ones with a head coordinate, and the final counts. Run the inherited `verify.py` to replay the sparse/sparse compatibility proofs themselves. No pair containing an older, non-universal dense-owner cap is asserted compatible or retained.

From this directory, `python verify.py` replays both dense checkers
and the sparse transfer. The second C++ implementation generates
RM(2,6) as the Plotkin split (u,u+v) with u in RM(2,5) and v in RM(1,5),
independent of the Gray traversal. For the 62D transfer the amplitude-2
weight-16 layer has zero tail, so its dense cross bound depends only on
the ordinary body's L1 bound. For 64D, 66D and 67D the inherited sparse
cross bounds use the indicated L1 threshold only, with dense points zero
on any extra coordinates. The predecessor certificates supply all
sparse/sparse checks; old nonuniform dense-owner additions are not used.

## 63D section

Intersect the complete 64D configuration with x₂=x₄₁ (zero-based).
Each cubic coset has full projection rank on these two coordinates, so
exactly half of its dense words survive. Among the verified weight-16
supports, 18,352 contain neither mark, 1,960 contain both, and the
others contain exactly one and are discarded. The retained affine
[16,11,4] sign charts have no dual word of weight two, so on a
double-covered support exactly half of the 2,048 signs survive.
This gives 167,772,160 dense, 39,591,936 weight-16, 146,568
weight-four and 124 axial points, for **207,510,788**. The exact
section inherits every pairwise angle from 64D.
